# RevPilot AI — Agent-Readable Commerce API

This is the machine-readable contract an AI buyer (or any external agent)
uses to discover and query a merchant's catalog. It's deliberately
separate from the merchant console's internal APIs — an agent integrating
against this contract never needs to understand RevPilot's frontend.

**The one rule that governs this entire surface**: every price, stock
count, and product relationship returned here is read live from the
database at request time. Nothing is generated by an LLM, nothing is
cached-and-possibly-stale in a way that matters, and a query that finds
nothing returns an honest empty result — never a plausible-sounding
guess. See `app/catalog/agent_catalog.py` for the implementation this
document describes.

Base path: `/api/v1/agent`. All endpoints require a `merchant_id` query
parameter (UUID). Authentication for this surface is not yet built (see
`docs/roadmap-testing-deployment.md`); today it inherits whatever network
boundary the deployment sits behind.

## Errors

Every error uses the same envelope as the rest of the API:
```json
{ "error": { "code": "STRING", "message": "STRING", "request_id": "req_x", "details": {} } }
```
Common codes on this surface: `MERCHANT_NOT_FOUND` (404),
`PRODUCT_NOT_FOUND` (404), `INVALID_INTENT` (422).

## `GET /api/v1/agent/catalog`

Lists every active product for a merchant.

**Query params**: `merchant_id` (required), `page` (default 1), `page_size` (default 20, max 100)

**Response**:
```json
{
  "items": [ /* array of Product objects, see below */ ],
  "page": 1,
  "page_size": 20,
  "total": 12
}
```

## `GET /api/v1/agent/catalog/search`

Filtered product search.

**Query params**: `merchant_id` (required), `q` (text match against name/description), `min_price`, `max_price`, `category` (name match), `in_stock_only` (bool, default false), `page`, `page_size`

Response shape matches `/catalog`.

## `GET /api/v1/agent/products/{product_id}`

Single product detail.

**Query params**: `merchant_id` (required)

**404** if the product doesn't exist *or* belongs to a different
merchant — the response is identical either way, so a caller can never
distinguish "wrong ID" from "not your product" (this is a deliberate
tenant-isolation choice, not an oversight).

### Product object shape
```json
{
  "id": "uuid",
  "sku": "TN-MOUSE-001",
  "name": "Pro Wireless Gaming Mouse",
  "description": "Lightweight wireless gaming mouse...",
  "price": { "amount": 1499.0, "currency": "INR" },
  "availability": { "in_stock": true, "stock_status": "in_stock", "quantity": 82 },
  "category": "Mice",
  "specifications": { "dpi": "26000" },
  "tags": ["wireless", "gaming"],
  "use_cases": ["gaming", "office"],
  "compatibility": ["Windows", "macOS", "Linux"],
  "related_products": [{ "id": "uuid", "name": "..." }],
  "frequently_bought_with": [{ "id": "uuid", "name": "..." }],
  "compatible_products": [{ "id": "uuid", "name": "..." }],
  "return_policy": "7-day free returns...",
  "shipping_info": "Ships in 2-4 business days...",
  "discount_eligible": true,
  "purchase": { "available": true }
}
```

`purchase.available` is `false` whenever `stock_status == "out_of_stock"`
or the product's internal status isn't `active` — this is the single
field an AI buyer should check before proposing a checkout for this item.
`related_products` / `frequently_bought_with` / `compatible_products` are
populated directly from the `product_relations` table — if a merchant
hasn't defined a relationship, the array is empty, never inferred.

## `GET /api/v1/agent/categories`

**Query params**: `merchant_id` (required)

```json
{ "items": [{ "id": "uuid", "name": "Gaming Accessories", "product_count": 4 }] }
```
`product_count` counts only active products — matches what `/catalog`
would actually return for that category.

## `GET /api/v1/agent/recommendations`

Deterministic keyword-matched recommendations — **not an LLM call**. See
"How ranking works" below.

**Query params**: `merchant_id` (required), `intent` (required, free text,
e.g. `"gaming setup"`), `max_price` (optional), `limit` (default 5, max 20)

```json
{ "items": [ /* Product objects */ ], "found": true }
```
`found: false` with an empty `items` array means genuinely nothing
matched — this is the expected, correct response for an intent the
catalog can't serve, not an error.

### How ranking works
Intent text is split into terms (words longer than 2 characters). Each
in-stock, active, budget-eligible product is scored by how many of those
terms appear in its `use_cases`, `tags`, or `name` (case-insensitive
substring match). Products are ranked by match count, then by price
ascending as a tiebreak. A product with zero matches is excluded
entirely — it is never included "just in case." Out-of-stock products
are excluded outright, regardless of how well they'd otherwise match:
recommending something that can't be purchased isn't useful to a buyer.

## What's intentionally NOT here yet

Cart, checkout, and order endpoints (`POST /agent/cart`,
`/agent/checkout/preview`, `/agent/checkout/confirm`,
`GET /agent/orders/{id}`) are the AI Buyer's conversational commerce
layer, built in the phases that follow this catalog (see
`docs/roadmap-testing-deployment.md`). This document will be extended
when they land; the same "nothing fabricated, every number recomputed
server-side" rule applies to all of them.
